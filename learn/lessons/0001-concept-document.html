개념 문서 한 장, 검색기가 읽는 단위

이 레슨이 끝나면 명세에 맞는 policies/returns.md를 손으로 써서 검사기를 통과시킨다.

약 25분읽기 8 · 퀴즈 5 · 실습 12용어: 핵심 규칙과 용어집

2026-11-19 OKF v0.3 기준으로 갱신했다. v0.2에서 바뀐 점은 docs/okf-v0.3-changes.md에 있다.

왜 이것부터인가

목표는 질문마다 맞는 문서를 골라 경로를 근거로 붙이는 RAG다. 이때 retrieve.ts가 골라서 모델에 넘기고 답변에 인용하는 단위는 모두 개념 하나다. 개념 한 장의 구조를 알아야 검색기가 무엇을 읽을 수 있는지 정할 수 있다.

1. 개념은 두 부분으로 된 파일 하나다

개념은 UTF-8 Markdown 파일 하나다. 파일 맨 위 --- 두 줄 사이에 YAML frontmatter가 있고 그 뒤가 본문이다.§4

---
type: Policy
title: 반품 정책
description: 반품 신청 기한과 할인 상품 규칙.
tags: [반품, 할인]
---

# 반품 조건

할인 상품을 포함해 수령 후 7일 이내에 반품을 신청할 수 있다.
  • 반드시 있어야 하는 키는 type 하나뿐이다. 값이 비어 있으면 안 된다. type만 있는 개념도 적합하다.§4.1
  • title, description, resource, tags는 선택이다. 반품 정책처럼 가리킬 실물 자산이 없는 개념은 resource를 생략한다.§4.1
  • type 값은 중앙 등록이 없다. Policy, Process는 이 실습에서 고른 이름이다.§4.1

v0.3: 어떤 파일이 개념인가

  • 개념 판별. 예약 파일이 아니고 frontmatter에 비어 있지 않은 type이 있는 .md만 개념이다. frontmatter나 type이 없는 .md(README.md 같은 파일)는 틀린 개념이 아니라 개념이 아닌 파일이다. 소비자는 건너뛰고, 번들 적합성에도 영향이 없다. 검증기는 경고하는 편이 좋다(SHOULD). .md가 아닌 파일은 asset이고, 이름이 .으로 시작하는 파일·디렉터리는 번들에 들지 않는다.§3.2
  • frontmatter 문법. 첫 줄과 끝 줄은 정확히 ---, YAML 1.2 매핑, 키 중복 금지. 숫자·불리언처럼 보이는 값은 따옴표로 감싼다. 이 규칙을 어겨 파싱이 안 되면 여전히 적합하지 않다.§4
  • 확장 키. 명세에 없는 키는 어느 단계에나 더해도 된다. 소비자는 모르는 키로 문서를 거부하지 않는다. 자기 키는 x-<producer>-<name>(예: x-acme-owner)으로 짓는 편이 좋다.§4.1
  • 빈 값. null, 빈 문자열, 빈 목록은 키가 없는 것과 같다. tags: 반품처럼 목록 대신 값 하나를 쓰면 태그 하나로 읽고 쉼표로 나누지 않는다.§11.2

검색기 관점: frontmatter는 고르는 데(분류·필터·미리보기), 본문은 답하는 데 쓴다. 6회차에서 "본문만" 검색과 "+분류" 검색을 비교하는 이유가 여기 있다.

2. 이름이 곧 ID다

개념 ID는 번들 루트 기준 경로에서 .md를 뺀 값이다.§2 이 실습의 번들 루트는 bundles/knowledge/이므로 bundles/knowledge/policies/returns.md의 ID는 policies/returns다.

index.md와 log.md는 예약 이름이라 개념 문서에 쓸 수 없다.§3.1 예약 파일은 frontmatter가 있어도 개념이 아니다. 하위 디렉터리 인덱스는 frontmatter를 갖지 않고, 번들 루트 index.md만 okf_version: "0.3", title, description, license 같은 번들 메타데이터를 둘 수 있다.§8§8.1

3. 링크가 관계를 만든다

본문의 일반 Markdown 링크가 개념 사이의 관계다. 번들 루트 기준(/processes/refunds.md)과 그 파일이 있는 디렉터리 기준 상대 경로(../processes/refunds.md)는 동등하게 유효하고, 명세는 어느 쪽도 권장하지 않는다. 소비자는 두 형식을 모두 해석해야 한다.§6 어떤 관계인지는 링크 주변 문장이 말한다. [[wikilink]] 같은 다른 문법은 OKF 링크가 아니다.§6.1

소비자는 끊어진 링크를 받아들여야 한다. 아직 쓰지 않은 지식일 수 있기 때문이다.§6.1 그래서 validate.ts는 끊어진 링크를 오류가 아니라 경고로 낸다.

4. RAG에서 누가 무엇을 하나

단계하는 일이 실습에서
검색질문에 맞는 개념을 고른다retrieve.ts (소비 도구)
전달고른 본문과 경로를 모델 입력에 넣는다5회차에서 붙여 넣기 → 이후 Claude SDK
생성받은 내용으로 답을 쓰고 근거 경로를 붙인다채팅 모델

OKF는 지식을 표현하는 형식일 뿐이다. 저장·서빙·질의 인프라는 명세가 정하지 않는다.§1 Non-goals 검색 단계와 생성 단계를 나누는 생각은 RAG 원 논문에서 왔다.Lewis et al.

5. 기억에서 꺼내기

위로 스크롤하지 말고 답한다. 다시 떠올리는 노력이 기억을 오래 남긴다. 점수:

Q1. 모든 개념 문서에 반드시 있어야 하는 frontmatter 키는?

  1. title 키 하나
  2. tags 키 하나
  3. type 키 하나
  4. resource 키 하나

Q2. 번들 루트가 bundles/knowledge/일 때 bundles/knowledge/policies/returns.md의 개념 ID는?

  1. bundles/knowledge/policies/returns
  2. policies/returns
  3. policies/returns.md
  4. returns

Q3. 검색기가 대상 파일이 없는 내부 링크를 만나면?

  1. 번들을 거부하고 읽기를 멈춘다
  2. 링크 대상을 자동으로 만든다
  3. 해당 문서만 조용히 건너뛴다
  4. 경고만 남기고 계속 읽는다

Q4. 질문에 맞춰 모델에 넘길 개념을 고르는 주체는?

  1. 소비 도구가 고른다
  2. OKF 명세가 정한다
  3. 채팅 모델이 고른다
  4. 번들 인덱스가 고른다

Q5. index.md에 frontmatter를 둘 수 있는 경우는?

  1. 모든 디렉터리에서 자유롭게
  2. 하위 디렉터리에서만 가능
  3. 번들 루트 하나에서만
  4. 어디서도 둘 수 없다

Q6. 번들에 frontmatter 없는 README.md가 있다. v0.3에서는?

  1. 번들이 적합하지 않게 된다
  2. 개념이 아닌 파일로 건너뛴다
  3. type을 자동으로 채운다
  4. 오류를 내고 읽기를 멈춘다

6. 실습: 반품 정책 개념 쓰기

위의 예시를 보지 말고 policies/returns.md를 처음부터 쓴다. 검사기에 아무 경고 없이 "적합한 개념 문서입니다"가 나오면 끝이다.

  1. 사실은 두 개다. ① 할인 상품을 포함해 수령 후 7일 이내 반품 신청 가능. ② 최종 판매 상품은 예외이고 승인 뒤 일정은 환불 절차를 따른다.
  2. 예외 개념(policies/return-exceptions.md)과 환불 절차(processes/refunds.md)로 가는 링크를 하나씩 넣는다. 하나는 상대 경로, 하나는 번들 루트 기준 경로로 써 본다.
  3. 일부러 틀려 본다. type을 지우고 tags: 뒤 공백을 빼고 링크 경로를 /policy/refunds.md로 바꿔서 각각 어떻게 보고되는지 본다. type을 지우면 오류가 아니라 "개념이 아니다" 경고가 나온다. 3회차 validate.ts도 같은 수준으로 보고한다.

브라우저 안 간이 검사기다. v0.3 명세 §3.2·§4·§4.1·§5·§6·§11 규칙을 src/okf/validate.ts와 같은 수준(오류·경고)으로 확인하지만 YAML 전체를 파싱하지는 않는다. 입력은 이 브라우저에 자동 저장된다.

힌트 (막혔을 때만 열기)

링크는 본문에 문장으로 넣는다. 관계는 문장이 설명한다. 예: "예외 상품은 [반품 예외](……)를 확인한다." 같은 디렉터리라면 파일 이름만으로도 된다.

통과한 내용을 저장소의 bundles/knowledge/policies/returns.md로 옮겨 저장하면 2회차 준비가 된다.
