검색 설정 비교

같은 질문을 세 가지 검색 설정으로 돌려 표로 비교한다. 문서 분류와 링크가 결과를 언제 바꾸는지 직접 확인한다.

약 90분회상 5 · 읽기 15 · 퀴즈 5 · 실습 50 · 검토 15용어: 핵심 규칙과 용어집

왜 이것이 다음인가

4회차에는 기본 설정 하나(본문+분류, 링크 on)로만 검색했다. 그래서 "불필요한 개념이 많다"는 관찰은 있어도 그 원인이 분류 필드인지 링크인지 가를 수 없었다. 오늘은 한 번에 한 가지만 바꿔 비교한다. 학습 계획 6회차의 완료 기준은 결과표에 세 종류의 사례를 남기는 일이다. 문서가 빠진 사례, 불필요한 문서가 더해진 사례, 링크 확장이 유효했던 사례.

시작 전 확인. 오늘 코드는 0004의 retrieve만 쓴다. 0005의 모델 답변 저장(answers/qN.txt)이 남아 있어도 진행할 수 있다. 그 경우 회상 1번은 0005 실습을 마친 뒤에 다시 답한다.

0. 회상

질문 6에서 검색이 넘긴 개념과 모델 답변을 보고, 검색과 생성 중 어느 단계가 막았는지 말한다.

기본 설정의 검색은 질문 6에도 return-exceptions.md와 returns.md를 넘긴다. 검색은 막지 못했다. 막는 곳은 생성 단계의 지시문("근거가 없으면 번들에서 확인할 수 없다고 답해 줘")이다. 오늘 실습 3단계에서 검색 단계에서도 막을 수 있는지 본다.

check-answer가 통과했는데도 틀린 답일 수 있는 경우를 하나 든다.

인용 경로는 맞는데 내용이 다른 경우다. [policies/returns.md]를 붙이고 "14일 이내"라고 쓰면 형식 검사는 통과한다. 내용은 사람이 파일을 열어 확인한다.

OKF의 sources와 각주는 0005의 경로 인용과 무엇이 같고 무엇이 다른가?

같은 점: 주장 단위로 근거를 붙인다. 다른 점: 경로 인용은 답변이 번들 안의 개념을 가리킨다. sources와 각주는 개념이 자신을 만든 자료를 가리킨다.§5.1 근거의 근거다. 0007에서 다룬다.

1. 세 설정과 통제 변인

설정점수를 매기는 글링크 한 단계CLI
본문본문안 따라감--fields body --no-links
본문+분류본문 + type·title·description·tags안 따라감--fields body+meta --no-links
본문+분류+링크위와 같음따라감기본값

첫째 줄과 둘째 줄은 분류 필드만 다르다. 둘째 줄과 셋째 줄은 링크만 다르다. 이렇게 짝을 지어야 차이가 어디서 왔는지 말할 수 있다. 상한(--max)과 기준(--min)은 세 설정이 같아야 한다. 4회차 실험에서 --max 1이면 링크 단계가 아무것도 더하지 못했다. 상한이 다르면 링크의 효과와 상한의 효과가 섞인다.

명세가 말하는 것과 말하지 않는 것

  • 분류 필드의 용도. type은 소비자가 라우팅과 필터링에 쓴다. description은 개념을 요약한 한 문장이고 인덱스 생성, 검색 스니펫, 미리보기에 쓰인다. tags는 여러 개념을 가로지르는 분류다.§4.1 본문을 다 읽기 전에 개념을 고르게 돕는 정보다. 인덱스가 같은 목적(점진적 공개)을 가진다.§8
  • 링크가 담는 것. 개념 A에서 B로 가는 링크는 관계가 있다는 주장이다. 관계의 종류(부모·자식, 참조, 의존)는 링크가 아니라 주변 문장이 전한다. 그래프를 만드는 소비자는 보통 모든 링크를 종류 없는 방향 간선으로 다룬다.§6.1 우리 검색기도 그렇게 한다. 링크 주변 문장이 질문과 관계있는지는 보지 않는다.
  • 명세가 정하지 않는 것. 검색 방법은 명세 범위 밖이다. 두 글자 묶음 점수, 상한, 기준, 링크 한 단계는 모두 이 과정에서 정한 설계다. 오늘 결과는 "OKF의 성질"이 아니라 "이 번들과 이 검색기의 성질"로 기록한다.

  4. 질문 1~6만으로는 완료 기준의 사례가 다 나오지 않을 수 있다. 그러면 질문을 직접 만든다. 2절 실험대에서 두 가지를 찾는다.
    • q7: 본문만 보면 기대 근거를 놓치고, 분류를 더하면 찾는 질문.
    • q8: 키워드로는 기대 근거를 못 고르지만 링크로 들어오는 질문.
    찾았으면 QUESTIONS 끝에 { id: 'q7', text: '…', expected: ['…'] }처럼 더하고 2단계를 다시 돌린다. 기대 근거는 질문을 만들기 전에 정한다. 결과를 보고 정하면 실험이 아니다.

힌트: q7과 q8을 찾는 단서 (실험대에서 10분 찾아본 뒤에 열기)
  • q7: 세 개념의 description을 본문과 한 단어씩 대조한다. description에만 있고 본문에는 없는 단어가 하나 있다.
  • q8: returns.md 본문의 링크 문장 "반품 승인 이후의 일정은 [환불 절차](…)를 따른다"를 본다. 환불 시점을 묻되 "환불", "승인" 같은 말을 쓰지 않으면 refunds.md는 키워드로 걸리지 않는다.
모범 답안: judge와 compare (테스트를 직접 통과시킨 뒤에 열기) 
export function judge(picks: Pick[], expected: string[]): Judgement {
  const got = new Set(picks.map((p) => p.path));
  const want = new Set(expected);
  return {
    missing: expected.filter((e) => !got.has(e)),
    extra: picks.filter((p) => !want.has(p.path)).map((p) => p.path),
    linkHelped: picks.filter((p) => p.via === 'link' && want.has(p.path)).map((p) => p.path),
  };
}

export function compare(bundle: Bundle, questions: Question[], settingList: Setting[]): Row[] {
  return questions.flatMap((question) =>
    settingList.map((s) => {
      const { picks } = retrieve(bundle, question.text, s.options);
      return { question, setting: s.name, picks, ...judge(picks, question.expected) };
    }),
  );
}

5. 검토: 결과를 읽는 법

표를 다 채운 뒤 아래를 확인한다.

  • 번들 크기를 함께 적는다. 개념이 3개이고 상한이 3개다. 링크를 켜면 번들 전체가 넘어가기 쉽다. 이 조건에서 나온 "링크는 불필요하다"는 결론이 개념 수백 개짜리 번들에도 맞는지는 이 실험으로 알 수 없다.
  • 분류 필드의 효과는 본문과 얼마나 겹치느냐에 달렸다. 지금 번들은 title과 tags의 단어가 대부분 본문 제목이나 문장에도 들어 있다. 본문이 길고 description이 그것을 요약하는 번들이라면 차이가 커질 수 있다.
  • 기준을 올리는 일과 링크를 켜는 일은 서로 영향을 준다. 키워드에서 떨어진 개념이 링크로 다시 들어올 수 있다. 표의 "점수" 칸과 "링크" 표시를 같이 본다.
