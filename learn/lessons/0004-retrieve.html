0. 회상

검증기가 끊어진 링크를 오류로 내면 검색기에 어떤 문제가 생기나?

번들 하나에 링크 하나만 끊겨도 번들 전체를 못 읽게 된다. 명세는 소비자에게 끊어진 링크를 참고 계속 읽으라고 요구한다.§11 오늘 검색기도 끊어진 링크는 경고만 남긴다.

validateBundle이 파일 경로 대신 Map을 받는 이유 두 가지는?

테스트에서 디스크 없이 번들을 문자열로 만들 수 있다. 그리고 나중에 웹 화면에서 브라우저가 가진 파일 내용만으로 같은 함수를 돌릴 수 있다. retrieve도 같은 방식이다.

../policies/../processes/refunds.md를 정규화하지 않으면 무엇이 중복되나?

같은 processes/refunds.md가 다른 문자열로 두 번 들어간다. 오늘 R4단계는 resolveLink로 정규화한 경로끼리 비교해서 중복을 막는다.

1. 한국어 키워드는 두 글자씩 자른다

띄어쓰기로만 자르면 "상품을"과 "상품"이 다른 단어가 된다. 조사와 어미가 붙기 때문이다. 형태소 분석기 없이 이 문제를 줄이는 흔한 방법이 두 글자 묶음(bigram)이다. Elasticsearch의 기본 CJK 분석기도 한·중·일 텍스트를 이렇게 자른다.Elasticsearch

"할인 상품을"  →  할인 · 상품 · 품을
"상품도"       →  상품 · 품도        ← "상품"이 겹친다

점수는 질문과 개념이 공유하는 묶음 수다. 단어 사이를 건너는 묶음은 만들지 않고, 한 글자 단어("수", "지")는 버린다. 대소문자도 낮춰 비교하므로 type: Policy와 policy는 같은 키워드가 된다. 앞서 물어본 대소문자 문제를 소비자 쪽에서 막는 방법이다.

직접 넣어 보기

아래는 실제 knowledge/ 개념 3개(본문 + type·title·description·tags)다. 질문을 바꿔 가며 점수가 어떻게 움직이는지 본다. 특히 "5일 됐어요"가 왜 환불 절차를 끌어오는지 찾아본다.

2. 링크는 한 단계만, 중복 없이

  1. 키워드로 고른다. 점수가 minScore(기본 2) 이상인 개념을 점수순으로 maxDocs(기본 3)개까지.
  2. 링크를 한 단계 따라간다. 키워드로 고른 개념의 링크만 본다. 링크로 들어온 개념의 링크는 따라가지 않는다. 한 단계를 넘기면 관련 없는 개념이 빠르게 늘어난다(학습 계획 §4 구현 순서 2).
  3. 상한을 지킨다. 링크로 더한 개념도 maxDocs에 포함된다. 6회차 비교에서 설정마다 같은 상한을 쓰기 위해서다.
  4. 이유를 남긴다. 키워드로 고른 개념은 점수와 겹친 묶음을, 링크로 더한 개념은 출발 개념을 기록한다. 끊어진 링크·번들 밖 링크·상한 초과는 warnings로 남기고 계속한다.

인덱스(index.md)는 검색 대상에서 뺀다. 인덱스는 길 안내용이고 답의 근거는 개념 본문에서 가져온다.§8

R5단계 기대값은 정답이 아니라 이 알고리즘의 현재 동작이다. 질문 1에 refunds.md가 끼고 질문 6에 엉뚱한 개념이 걸리는 것도 그대로 기록되어 있다. 무엇이 문제인지 판단해서 evaluation.md에 적는 것이 오늘의 검토 과제다.

모범 답안: score와 retrieve (테스트를 직접 통과시킨 뒤에 열기) 
export function score(question: string, c: Concept, fields: Options['fields']): { score: number; matched: string[] } {
  const doc = bigrams(searchText(c, fields));
  const matched = [...bigrams(question)].filter((b) => doc.has(b)).sort();
  return { score: matched.length, matched };
}

export function retrieve(bundle: Bundle, question: string, options: Partial<Options> = {}): Result {
  const opt = { ...DEFAULT_OPTIONS, ...options };
  const concepts = readConcepts(bundle);
  const byPath = new Map(concepts.map((c) => [c.path, c]));
  const picks: Pick[] = [];
  const warnings: string[] = [];

  // 1) 키워드로 고르기: 점수 내림차순, 같으면 경로순. minScore 이상, maxDocs까지.
  const ranked = concepts
    .map((c) => ({ c, ...score(question, c, opt.fields) }))
    .filter((r) => r.score >= opt.minScore)
    .sort((a, b) => b.score - a.score || a.c.path.localeCompare(b.c.path));
  for (const r of ranked.slice(0, opt.maxDocs)) {
    picks.push({ path: r.c.path, via: 'keyword', score: r.score, matched: r.matched });
  }

  // 2) 링크 한 단계: 키워드로 고른 개념의 링크만 본다. 링크로 추가한 개념의 링크는 따라가지 않는다.
  if (opt.followLinks) {
    const seeds = picks.filter((p) => p.via === 'keyword');
    for (const seed of seeds) {
      for (const raw of byPath.get(seed.path)!.links) {
        const target = resolveLink(seed.path, raw);
        if (target === null) {
          warnings.push(`${seed.path}의 링크 ${raw}가 번들 밖을 가리켜 건너뛴다.`);
          continue;
        }
        if (picks.some((p) => p.path === target)) continue; // 중복 제거 (정규화한 경로로 비교)
        if (!byPath.has(target)) {
          warnings.push(`${seed.path}의 링크 ${raw}(${target})가 번들에 없어 건너뛴다.`);
          continue;
        }
        if (picks.length >= opt.maxDocs) {
          warnings.push(`상한 ${opt.maxDocs}개에 걸려 ${target}를 추가하지 않았다.`);
          continue;
        }
        picks.push({ path: target, via: 'link', score: 0, matched: [], from: seed.path });
      }
    }
  }
  return { picks, warnings };
}
