Reference · OKF v0.3

핵심 규칙과 용어집

레슨에서 쓰는 용어는 이 문서를 따른다. 출처는 모두 OKF v0.3 명세(커밋 527e81a).

2026-11-19 v0.2 요약본(okf-v0.2-core.html)을 v0.3 기준으로 고쳐 이름을 바꿨다. v0.2에서 바뀐 점과 절 번호 대응표는 docs/okf-v0.3-changes.md에 있다. 저장소 전체 용어는 GLOSSARY.md를 따른다.

개념 문서 한 장

---
type: Policy          # 필수 (유일), 비어 있지 않게
title: 반품 정책        # 선택
description: 한 줄 요약  # 선택
tags: [반품, 할인]      # 선택, YAML 목록
# resource: URI       # 선택, 자산 없으면 생략
# x-acme-owner: cs    # 확장 키
---

# 반품 조건           ← 본문 (CommonMark)

[반품 예외](return-exceptions.md)
[환불 절차](../processes/refunds.md)
  • UTF-8 .md. 첫 줄과 끝 줄이 정확히 ---인 YAML 1.2 매핑 + 본문. 키 중복 금지, 숫자·불리언처럼 보이는 값은 따옴표. §4
  • 항상 필요한 키는 비어 있지 않은 type 하나. type만 있어도 적합. §4.1
  • frontmatter나 type이 없는 .md는 개념이 아니다. 소비자는 건너뛰고, 검증기는 경고한다. §3.2
  • type 값은 중앙 등록이 없다. 직접 고른다. §4.1
  • 확장 키는 어느 단계에나 둘 수 있다. 소비자는 모르는 키로 거부하지 않고, 파일을 고치는 생산자는 모르는 키를 지킨다. 자기 키는 x-<producer>-<name>. §4.1
  • 본문은 CommonMark + GFM 표 + [^label] 각주. 각주 라벨은 sources 항목의 id. §4.2

YAML 목록과 빈 값

tags: [반품, 예외]   # flow
tags:               # block
  - 반품            # 공백 들여쓰기 (탭 금지)
  - 예외

키: 뒤에는 공백. 출처: YAML 1.2.2 §7.4.1 · §8.2.1 · §6.1

  • null, 빈 문자열, 빈 목록은 키가 없는 것과 같다.
  • 목록 필드(tags, sources, verified, parameters)는 항목 하나를 목록 하나로 읽는다. 스칼라 tags: 반품, 예외는 태그 하나다. 쉼표로 나누지 않는다.
  • 필수 키가 없는 항목(예: at 없는 verified 항목)은 무시하고 경고한다.

출처: §11.2 Consumer rules.

번들의 파일 종류

파일규칙근거
루트 index.md목차. frontmatter에 번들 메타데이터 okf_version: "0.3", title, description, license와 확장 키를 둘 수 있다. okf_version을 두는 편이 좋다(SHOULD). 인덱스를 다시 만들 때 기존 frontmatter를 지킨다(MUST).§8 · §8.1
하위 index.md제목 아래 * [제목](경로) - 설명 목록. frontmatter 없음.§8
log.md어느 수준에나 선택적으로. ## YYYY-MM-DD 날짜 묶음, 최신순. frontmatter 없음.§9
type 있는 .md개념. 예약 이름(index.md·log.md)은 frontmatter가 있어도 개념이 아니다.§3.1 · §3.2
frontmatter·type 없는 .md개념이 아니다(README.md 등). 건너뛰고, 적합성에는 영향 없음.§3.2
.md가 아닌 파일asset(그림, 코드 등). 링크·경로 필드의 대상이 될 수 있지만 개념이 아니다.§3.2
.으로 시작하는 이름번들에 들지 않는다(.git, .obsidian …). 번들 밖으로 나가는 심볼릭 링크도 따라가지 않는다.§3.2

링크와 경로

본문 링크와 경로 필드는 같은 규칙으로 푼다. §6

형식예 (policies/returns.md 안에서)해석
URI 스킴 있음https://example.com/faq절대 URL
/로 시작 (번들 루트 기준)/processes/refunds.mdprocesses/refunds.md
그 밖 (파일 디렉터리 기준)../processes/refunds.mdprocesses/refunds.md
같은 디렉터리return-exceptions.mdpolicies/return-exceptions.md
번들 밖../../faq.md외부. 로컬 파일 시스템에서 읽지 않는다
  • 번들 안 두 형식은 동등하게 유효하고 명세는 어느 쪽도 권장하지 않는다(v0.2는 링크에 /를 권장했다). 소비자는 둘 다 해석해야 한다.
  • 값은 URI 참조다. 공백은 %20으로 인코딩하고, 경로는 대소문자를 구별한다.
  • #fragment를 뺀 대상이 개념 파일일 때만 개념을 가리키는 링크다. [[wikilink]]는 OKF 링크가 아니다. 끊어진 링크는 잘못된 것이 아니라 아직 안 쓴 지식일 수 있다. §6.1
  • 경로 필드: resource, sources[].resource, superseded_by, computation, executor.resource, attester.resource. sources[].resource가 범위 설명이면 경로가 아니다. §6.2
  • v0.2 대체 해석: / 없는 경로 필드가 파일 기준으로 풀리지 않고, 번들이 okf_version 0.2 이하이거나 선언이 없으면 번들 루트 기준으로 다시 찾아도 된다(MAY). 본문 링크에는 없다. §12.1
  • 번들 그래프의 간선은 개념에서 개념으로 가는 링크와, 개념으로 해석되는 경로 필드 두 종류다. §6.4

주의: 일반 Markdown 미리보기와 GitHub는 /를 저장소 루트로 해석한다. 번들이 저장소 하위 디렉터리(bundles/knowledge/)에 있으면 번들 루트 기준 링크가 미리보기에서 깨진다. 그래서 이 실습은 본문 링크를 상대 경로로 쓰는 팀 규칙을 정했다(레슨 0002, docs/team-rules.md).

적합성: 오류와 경고의 경계

적합하지 않음 (오류)

  • .md의 frontmatter 블록이 YAML 매핑으로 파싱되지 않는다 (닫는 --- 없음 포함)
  • index.md·log.md가 §8·§9를 어긴다 (하위 index.md나 log.md의 frontmatter)

출처: §11.1

거부 금지 (경고 수준)

  • frontmatter나 type이 없는 .md (개념이 아님)
  • 선택 필드 누락, 빈 값, 필수 키 없는 항목
  • 모르는 type 값, 모르는 확장 키
  • 끊어진 링크
  • index.md 누락, okf_version 누락

출처: §11.2

용어집

번들 (bundle)
개념 문서를 담은 디렉터리 트리. 배포 단위. 이 실습에서는 bundles/knowledge/. §2, §3
번들 루트 (bundle root)
번들의 맨 위 디렉터리. /로 시작하는 경로의 기준. 저장소 하위 디렉터리일 때는 frontmatter 있는 루트 index.md가 번들 루트를 알려 준다. §2
번들 메타데이터
루트 index.md frontmatter의 okf_version·title·description·license. 번들에 적용되고 개념에는 적용되지 않는다. §8.1
개념 (concept)
번들 안의 지식 한 단위 = 비어 있지 않은 type이 있는 Markdown 파일 하나. 레슨에서는 "문서" 대신 이 말을 쓴다. §2, §3.2
개념 ID
번들 루트 기준 경로에서 .md를 뺀 값. frontmatter에 쓰지 않는다. bundles/knowledge/policies/returns.md → policies/returns. §2
asset
이름이 .md로 끝나지 않는 번들 파일(그림, 검증 코드 등). 개념이 아니다. §2, §3.2
frontmatter
파일 맨 위 --- 사이의 YAML 메타데이터. §2, §4
본문 (body)
frontmatter 뒤의 모든 내용. §2
확장 키 (extension key)
명세가 정의하지 않은 frontmatter 키. x-로 시작하는 키는 앞으로의 버전이 정의하지 않는다. §2, §4.1
링크 (link)
개념에서 다른 개념으로 가는 일반 Markdown 링크. 방향은 있지만 종류는 없는 관계. 부모·자식 구조는 디렉터리 트리만 만든다. §2, §6.1
경로 필드 (path field)
값이 경로나 URI인 frontmatter 필드(resource, sources[].resource, superseded_by 등). 링크와 같은 규칙으로 푼다. §2, §6.2
인덱스 (index)
디렉터리의 index.md. 문서를 열기 전에 무엇이 있는지 보여 주는 목차(점진적 공개). §8
생산자 / 소비자
번들을 쓰는 쪽(사람, 에이전트, 파이프라인) / 읽는 쪽(에이전트, UI, 검색 색인, 프로그램). §2
적합 (conformant)
모든 frontmatter 블록이 YAML 매핑으로 파싱되고, 예약 파일이 §8·§9를 지키는 상태. §11.1
출처 (source)
개념이 근거로 삼은 자료. frontmatter sources에 기록. §2, §5.1
행위자 (actor)
누가 했는지 나타내는 문자열. <producer>/<version> 또는 <scheme>:<id>(human:, team:, process: …). human:만 사람 검토 등급을 준다. §7
신뢰 등급 (trust tier)
현재 검토 기록(at이 generated.at과 같거나 늦은 verified 항목, generated가 없으면 모든 항목)으로 소비자가 계산하는 등급. unverified, machine-confirmed, human-reviewed. §2, §5.3
검색 단계 (retrieval)
RAG에서 질문에 맞는 개념을 골라 오는 단계. 이 실습에서는 retrieve.ts가 맡는다. Lewis et al.
생성 단계 (generation)
고른 본문을 입력으로 모델이 답을 쓰는 단계. Lewis et al.
근거 경로
답변의 주장 옆에 붙이는 개념 파일 경로. 이 실습에서 정한 용어. 학습 계획 §4
