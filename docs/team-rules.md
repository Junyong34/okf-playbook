# 번들 작성 팀 규칙

OKF v0.3 명세 위에 이 실습에서 추가로 정한 규칙이다(2026-11-19에 v0.2 기준에서 바꿨다). 명세가 허용하는 것을 오류로 만들지 않으며, 위반은 `validate.ts`가 경고(`team/*`)로 보고한다.

| 규칙 | 근거 | 검사 |
| --- | --- | --- |
| 번들 안 링크는 상대 경로로 쓴다 (`../processes/refunds.md`). `/`로 시작하는 번들 루트 기준 경로는 쓰지 않는다. | v0.3 명세는 `/`로 시작하는 번들 루트 기준 경로와 파일 디렉터리 기준 경로를 둘 다 유효하게 보고, 어느 쪽도 권장하지 않는다(§6, §13.2). 그래서 미리보기 기준으로 고른다. GitHub·에디터 미리보기는 `/`를 저장소 루트로 해석해 링크가 깨진다. 번들이 저장소 하위 디렉터리 `knowledge/`에 있기 때문이다. (2026-11-17, 레슨 0002. 2026-11-19 v0.3 기준으로 근거 수정: v0.2는 링크에 `/`를 권장했다) | `team/relative-links` |
| frontmatter의 경로 필드(`sources[].resource` 등)는 번들 루트 기준 경로(`/references/returns-faq.md`)를 쓸 수 있다. 위의 상대 경로 규칙은 본문 링크에만 적용한다. | 상대 경로 규칙의 이유는 미리보기가 본문 링크를 깨뜨리는 것인데, frontmatter 값은 링크로 그려지지 않는다. v0.3 명세는 경로 필드와 링크에 같은 해석 규칙을 쓰고 두 형식을 모두 허용한다(§6, §6.2). `/` 없는 값은 파일 디렉터리 기준으로 풀리므로(§13.1), 번들 루트 기준으로 쓰려면 `/`를 붙여야 한다. 명세 예시도 경로 필드에 `/`를 쓴다(§13.2). 학습 계획 §6-1도 이 형식을 쓴다. (2026-11-18, 레슨 0007. 사용자 요청으로 에이전트가 모범 답안대로 기록했다. 사용자 확인 필요. 2026-11-19 v0.3 기준으로 근거 수정) | 없음 |
